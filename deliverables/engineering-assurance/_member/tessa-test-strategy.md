# 验证策略评估 v2：pandora / LOS24 启动故障实验矩阵

**评估人**：泰莎（Tessa）· 测试专家
**v2 变更**：据构建笔记 §27 / §31 补入「E1a 历史上已执行且为阴性」，新增 S1-0（头号缺陷）、§2 历史观测可迁移性审计、§4 两臂判读表存续性判定，重排优先级。
**评估立场**：不评估静态推导是否正确，只评估这套实验能否真的判出结论、判错时能否被发现。

## 2. 历史观测盘点与可迁移性审计（v2 新增）

### 2.1 两条记录

| # | 出处 | 配置 | 操作 | 结果 |
|---|---|---|---|---|
| **H1** | 构建笔记 §27 | LOS 24 + **A16 blobs** | 刷入后卡动画 → **清 data** | **仍卡动画** |
| **H2** | 构建笔记 §31 | LOS 24 + A17 blobs，13 分区 | 刷前 **`fastboot -w`** | **重启循环** |

### 2.2 三维可迁移性判定

阴性要能采信，三维须全中：

| 维度 | H1 | H2 |
|---|---|---|
| 配置可迁移（blobs 世代） | ✗ A16 ≠ 当前 A17 | ✓ |
| 症状可迁移（同为「卡动画」） | ✓ | ✗ 是重启循环 |
| 操作语义可审计 | ✗ 「清 data」未定义 | ✗ `-w` 是否含 `erase metadata` 未定 |

H1 中两条、H2 中一条 → **两条都不能单独否证假设**。但合起来仍产出一条不依赖时序的硬结论：**「干净 /data」不足以启动**（H2 直接证明），且 H1 在症状不变的前提下 wipe 无效。即「是否 wipe /data」与「症状形态」间**没有观察到单调关系**——这对「/data 侧残留是首号嫌疑」是实质削弱。

### 2.3 覆盖度标记裁定

/data 行 E1a 列既不能标 ● 也不能标 ○：标 ● 错，● 语义是「能给出二值结论」，而 H1 配置不可迁移、操作不可审计；标 ○ 也错，会丢掉「干净 /data 不足以启动」这条真实信息，导致把不可逆操作重做一遍——正是 S1-0。故标 **⊘**，解冻条件见 §4.3。

## 3. 实验设计缺陷（按严重度）

### S1-0（头号）未盘点历史观测，把「已知阴性」当成「未知」重做一次不可逆操作

报告把 E1a 列为待做实验，而构建笔记已记录该实验做过且为阴性；§31 的 `fastboot -w` 又与 E1b 的 `-w` 部分重叠。测试工程上这是**用例库与执行记录脱节**：同一不可逆用例被重复立项，代价不是工时，而是**一次不可逆额度**。纪律：实验立项前先核「历史执行台账」，字段含配置指纹、命令原文、症状、结果。

### S1-1 「卡」是一个词，指两件事

E1a 的「卡」指 **TWRP 里 format 失败**；E1b 的「卡」指 **系统起不来停在动画**。两个不同的可观测量被同一张判读表混用。若 TWRP 因不支持该 fscrypt 策略版本而 format 失败，按现表会被记成「/data 侧残留成立」——**实验没执行，结论却落了盘**。

### S1-2 判读表存在方向性错误

现表「两臂都卡 ⇒ 残留假设整体排除」。但 E1b 卡住对「KeyMint 是否可用」是**反向证据**。且 H2 恰是本报告 5.8 方法论的反例：症状从「卡动画」变成「重启循环」，**不能记为「/data 假设被排除」，只能记为「症状改变、配置已变、不可比」**。

### S1-3 E2 与 wipe 的变量污染未声明

只声明了「E1b 排最后」，没声明 **E2/E2b 必须在任何 wipe 之前**。若先 wipe，E2 permissive 成功便无法区分「sepolicy 缺口」与「wipe 本身就好了」，且该混淆无法事后剥离。

### S2 级（四条，合并）

① **E-1 的「mount /data」跨执行体不成立**——TWRP vold 与 LOS init 非同一实现，须降级为弱信号；② **E3 是构造新配置而非控制变量**，「LOS system + 原厂 vendor」从未存在过，通过只能推出「该混合组合能起」；③ **E4 污染 slot 证据**，须晚于所有 getvar；④ **无观测窗口定义**，统一为「≥15 分钟无 `sys.boot_completed` 变化即判卡，并记录动画是否仍逐帧」。

### S3 级（合并）

E0 是静态结论却列入实验表；E5 / E6 编号缺失致审计链断裂；「完整快照」未定义。

## 4. E1a / E1b 两臂判读表的存续性

### 4.1 判定：原表已失效

原表是三行完备划分，前提是两臂皆未知且独立。现 E1a 有阴性先验 → 「E1a 过」近乎死分支。更关键：**若 `fastboot -w` 已含 `erase metadata`，则 E1b 亦已执行过，三行全死、原表整体作废**。故须替换为 §4.3 决策树。

### 4.2 四种「清」的语义差异（是否足以救回假设）

| 操作 | /data 文件系统 | metadata 分区 / key blob | 能否否证该假设 |
|---|---|---|---|
| 「清 data」（§27 原文） | 未知 | 未知 | 不能——语义不可审计 |
| TWRP format data | 重建（mkfs） | 取决于 TWRP 实现，可能只重建 /data 而保留旧 blob，**反而制造新的不匹配** | 不能，可能引入新故障 |
| `fastboot -w` | 重建 userdata | 取决于该设备构建产出的 `fastboot-info.txt` 是否含 `erase metadata`；已核 fastboot.cpp：`-w` 仅置 `wants_wipe`，实际擦除由 `if-wipe` 指令驱动，对 metadata 无硬编码保证 | 未定，须实证 |
| `fastboot erase metadata` | 不触碰 | **销毁 key blob，强制重建** | **能**——唯一语义确定的操作 |

结论：**四种里只有第四种语义确定**。前三种都在「保留旧 key blob」与「重建 key blob」间摇摆，而这正是假设成立与否的分水岭。故「差别是否足以救回假设」——**足以，恰恰因前三种不确定假设才存活；也正因不确定，不能靠推理，必须实测**。

### 4.3 替代决策树（前置门禁）

```
X2：TWRP 只读 /metadata/vold/metadata_encryption/ 下 key blob 的 mtime
├─ mtime 晚于 H1/H2 的清 data 时刻
│    ⇒ key blob 曾被重建，且重建后仍失败
│    ⇒ 残留假设「死亡」→ E1a / E1b 取消，零不可逆消耗
└─ mtime 停留在原厂 A17 首次启动
     ⇒ key blob 从未被重建，H1/H2 的阴性不成立
     ⇒ E1b 跃升为唯一有效臂，且可提前执行
```

这条门禁把「要不要做不可逆操作」从**判断**降级为**读数**。

## 6. 三态判定表（新增「已执行」态）

**无效态定义**：实验未执行、或执行了但观测失效。**无效态一律不得记为「排除」。**

| 实验 | 通过 | 失败 | **无效** |
|---|---|---|---|
| E-1 | `adb devices` 见 `device`，或 TWRP 能挂 /data 见明文 | 空列表 / offline 且两处均挂不上 | TWRP 未进入；主机 udev 未装致误报空 |
| E1a | TWRP 报 format 完成 **且** 重启后系统起 | format 完成 **但** 仍卡 ≥15 min | **format 报错 = 无效，不是失败**；**历史 H1 记为「已执行-⊘不可采信」** |
| E1b | `erase metadata` 返回 OK 且 `-w` 完成且系统起 | 命令 OK 但系统仍卡 ≥15 min | 命令返回 FAILED；**若 `fastboot-info.txt` 证明 `-w` 已含 erase metadata，则 H2 亦属「已执行」** |
| E2 | avc `permissive=0 → 1` 且能进系统 | 转 1 但仍卡 | 仍为 0；或见 `SELinux: Could not load policy` |
| E2b | 放宽后能进系统 | 放宽后仍卡 | 策略文件未真正进镜像（须校验镜像内哈希） |
| E3 / E4 | 混合配置能起 / 进 TWRP 可正常操作 | 仍卡 / 停 logo 黑屏 | 原厂 boot 未起 fastbootd；装错槽位 |
| E7 | 屏幕无 bootanimation 输出 | 仍见逐帧动画 | 关闭未生效（须确认属性真被读到） |

## 7. 优先级排序（v2 重排）

| 序 | 实验 | 变化与理由 |
|---|---|---|
| P0 | E-1（10 s） | 唯一能推翻「零日志」前提的观测 |
| P0 | TWRP 只读取证链（pstore → pmsg → /metadata → tombstones → dropbox） | 零风险零改动，且是 X2/X5 的数据源 |
| **P0** | **X2（门禁）** | **新增升级**：唯一能「取消」不可逆实验的实验 |
| P1 | `fastboot getvar all` | slot 证据，须早于 E4 |
| P1 | X4（oem 日志） | 零改动，可能一步定案 |
| P2 | E0（静态） | 省一次刷机 |
| P2 | E2 → E2b | 必须在任何 wipe 之前 |
| **P2（条件）** | **E1b** | **由 P6 升为条件性 P2**：仅在 X2 判定「key blob 从未重建」时执行，此时是唯一有效臂 |
| P3 | E7 / X5、E3 / X1（成对） | 验证全局前提与交叉对照 |
| P4 | E4 | 污染 slot 证据，须晚于 getvar |
| **取消** | **E1a** | **历史已执行（H1），且 TWRP format 语义不如 E1b 确定；除非 X2 给出相反信号，不再立项** |

**E1b 仍不得早于 X2**：X2 是零风险读数，E1b 是不可逆写入——先读后写是本矩阵唯一不可让渡的顺序。

## 8. 回归验证清单

假设确认后，验证「修复有效」而非「碰巧好了」：

1. **单变量修复**：只 wipe /data，其余镜像一字节不改。
2. **反向复现（最关键）**：刷回原厂 A17 → 由原厂加密 /data → 再刷 LOS 不 wipe，**故障必须复现**。只做正向不做反向，等于没证明因果。
3. **循环 ≥ 2 次**：正向 2/2、反向 2/2，否则结论降级为「相关」。
4. **两臂对照**：分别验证「wipe /data 保留 /metadata」与「erase metadata 保留 /data」，确认**只有前者修复**。
5. **时间窗口**：修复后 ≥ 3 次完整重启（含冷启动 ≥ 1 次）。
6. **判据锚点**：须同时满足 `sys.boot_completed=1`、vold 解密成功行、`nonencrypted` 触发记录，不以「看到 launcher」为通过。
7. **历史台账回填**：结论落盘时标注「新增 / 修正 H1 / 修正 H2」，防止下一轮再把已知阴性当未知。

**不可逆实验前落盘清单**：① E-1 四象限结论；② `getvar all` 全量；③ pstore / pmsg / tombstones / dropbox / `/metadata` 五处快照；④ 依赖「症状稳定」的全部判读；⑤ **X2 的 mtime 读数**；⑥ 原厂恢复脚本可用性实测（不能只在纸面假设 270 秒可回滚）。

## 9. 结论

v2 的核心变化不在覆盖度，而在**先验**：报告把「/data 侧残留」列为头号嫌疑并配一个待做实验，而项目自己的构建笔记里已躺着两次相关尝试——一次同症状阴性（H1）、一次异症状阴性（H2）。这使该假设的先验大幅下降，而验证代价是**一次不可逆操作**。

矩阵的顺序纪律（不可逆排最后、warm reset 收尾、E-1 前置）仍正确且罕见。但它缺一道**历史台账门禁**，也缺一条**用零风险读数取代不可逆写入**的通道——X2 恰好同时补上两者。若只采纳一条建议：**先读 key blob 的 mtime，再决定要不要 erase 它。**
